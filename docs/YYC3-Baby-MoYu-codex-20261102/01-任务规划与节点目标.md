# 📋 任务规划与节点目标

## 规划总则

> 执行有规划，规划有节点，节点有目标，目标可评估。

## 一、总体目标

1. 基于底层代码完成全局审计与实测，形成可追溯的审核报告与执行日志。
2. 修复远程 CI 红叉根因（Dependabot / 根类型检查 / 测试范围 / Pages 发布健壮性），并完善 CI 配置。
3. 按开源级标准补全 README、LICENSE、行为准则、贡献指南、安全政策、开发者文档与可视化交互体系设计。
4. 对审计发现的安全问题（Next.js 已知高危通告）完成升级并回归验证。
5. 全程**不提交**（沿用既有约束），交付可复核的本地变更与文档。

## 二、阶段划分

| 阶段 | 名称 | 目标 | 交付物 | 状态 |
| ---- | ---- | ---- | ---- | ---- |
| Phase 1 | 环境与基线 | 安装依赖、跑通五道门禁，建立真实基线 | 命令结果、审核报告 00 | ✅ |
| Phase 2 | CI 红叉修复 | 定位并修复 Dependabot 与根门禁阻断项 | `.github/dependabot.yml`、`tsconfig.json`、`package.json` | ✅ |
| Phase 3 | 安全升级 | 关闭 Next/zod/next-intl 已知通告并回归 | `package.json` / `bun.lock` | ✅ |
| Phase 4 | 文档体系 | README 徽章/标签、四大开源文档、10 号设计文档、Issue/PR 模板 | 根文档 + `docs/developer/10-*` | ✅ |
| Phase 5 | 验证与留档 | 五道门禁 + YAML 校验 + 会话日志 | 01/02/03 文档 | ✅ |

## 三、详细任务分解

### Task 1.1 依赖安装与基线

**目标**：在干净依赖状态下复现项目真实质量。
**验收标准**：

- [x] `bun install --frozen-lockfile` 成功
- [x] `bunx tsc --noEmit` → 0 error
- [x] `bun run lint` → 0 error
- [x] `bun run test` → 全绿
- [x] `bun run build` 成功

**完成标记**：✅

### Task 1.2 远程 CI 取证

**目标**：确认远程失败工作流与根因。
**验收标准**：

- [x] `gh run list` 确认 Dependabot 连续失败
- [x] 失败日志定位：`npm_and_yarn` 无法更新 `bun.lock`
- [x] 确认根 CI 最近一次成功、存在历史 queued 运行

**完成标记**：✅

### Task 2.1 CI 修复与加固

**目标**：修复根因并提升流水线健壮性。
**验收标准**：

- [x] 新增 `.github/dependabot.yml`（`bun` + `github-actions`，分组、限流、时区）
- [x] 根 `tsconfig` 排除 `docs`（避免归档工程污染类型检查）
- [x] `bun run test` 脚本排除 `docs/**`（避免 Vitest 工程被 Bun 执行）
- [x] `ci.yml` 增加权限、并发取消、超时、CI 环境变量
- [x] `deploy-pages.yml` 增加 `nullglob`、超时、顶图小写路径
- [x] 所有 YAML 通过解析校验

**完成标记**：✅

### Task 3.1 依赖安全升级

**目标**：关闭已知高危通告且不破坏构建。
